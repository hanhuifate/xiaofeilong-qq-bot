# 单一主会话与按需工具（2026-10-27）

当前生产 Codex 主线已切换为每个群或私聊一个持久 Thread，不再按日常/联网拆分。现有 2 个群和 2 个私聊已完成迁移，侧栏可见 4 条，全部位于“QQ 群聊”。旧 7 条路线已归档，原始聊天数据库未删除。当前模型仍为 GPT-6 Luna，思考强度 xhigh。

## 对话与长期记录

- 对话内依靠原生 Thread 记住已交流内容，后续只追加尚未见过的 QQ 事件；发送成功且正文与模型上一答一致时仅追加送达回执，不重放正文。
- 迁移时各对话一次性带入当前保留的近期交流：176、200、2、116 条。历史资料明确标记为 bootstrap，模型只确认接收，不执行其中的旧请求，也没有向 QQ 发送迁移消息。
- 更早聊天、关系和长期记忆留在 SQLite。日常输入不再自动检索并携带旧记录、关系档案、最早一句、图库和社会状态摘要；需要时由模型调用工具读取。
- 沿用 Codex 原生自动压缩，不按固定聊天时间清空上下文，不额外启动定时总结模型。宿主接受并记录 contextCompaction 完成事件。真实验收未刻意填满上下文来触发自动压缩，因此不能将其写成“已实际触发自动压缩”。
- 固定人设仍从独立 persona.json 编译为开发者指令，面板修改后刷新指令并保留同一 Thread。

日常新增包只包含本轮发言者、增量事件、当前请求来源 ID、当前能力与交流对象；必要时加入引用、图片和特殊互动类型。同一问题已存在于当前事件中时，不再重复一个 question 字段。身份配置仅在首次接入提供，之后需要时查询真实宿主身份。

## 工具往返

通过本机 Codex 可执行文件导出的真实实验性协议注册 dynamicTools；模型发起 item/tool/call，宿主执行受限工具，返回 inputText / inputImage，模型在原 Turn 内继续回答。不是先发一条“我要查”到 QQ 再新开聊天。

工具：

- qq_memory：当前对话数据库查询，或经过原权限过滤的跨对话查询。
- qq_context：按需读取身份、群权限、群友关系、图库、可戳对象和最早消息。
- qq_image / qq_avatar：返回实际图片像素，不把文字描述当成看过图片。
- qq_browser：在获准对话内使用既有隔离浏览器，返回实际截图；原测试去重和操作限制继续执行。
- qq_draw：提交豆包任务并返回 queued；后台等待原图后另行发图。
- qq_manage：调用独立管理权限与确认层，发起人从真实 QQ 事件绑定，模型不能自填管理员身份。
- qq_prepare_reply：仅在需要时提供图片、表情、戳戳、记忆更新、参与状态或回访提议，实际发送与记忆写入仍在最终阶段验权。

原生公开搜索在同一主会话中按需调用；搜索权限按对话配置决定。未开启 shell、电脑控制、其他 MCP 或插件能力。普通最终输出只有 shouldReply 和 text 两个字段，不再每次输出整个空的管理/浏览器/生图结构。

工具调用绑定当前 Thread、Turn、QQ 发起人、对话号和上下文版本；暂停或上下文失效后拒绝执行。生图与管理还会保存 SQLite 工具回执：相同来源的重复请求复用结果，执行结果不明时拒绝自动重放。混合多人批次不能继承最后发言人的跨对话或管理权限。
