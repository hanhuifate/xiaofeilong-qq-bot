# 社交与记忆离线评测

更新日期：2026-10-27

## 目标

评测重点不是“回复多少条”，而是：

- 明确找机器人时能够回应；
- 人类之间点名或延续对话时保持沉默；
- 连续短句合并，不把一句拆成多次回复；
- 被纠正后不重复错误，不靠反复自贬讨好；
- 不重复相同观点，不用模板填满沉默；
- 被拒绝、被忽略或超过频率边界时降低参与；
- 旧话题和引用仍然有来源，不混入其他群或私聊。

这些是离线回放与单元场景，不调用真实 QQ 群，也不代表自然度已经由真实群友验收。

## 纠错评测

纠错采用证据记账：

1. 模型只能从本轮真实用户消息引用 `sourceIds`；
2. 证据指向一条实际存在的机器人回复；
3. 同一对话、同一主题至少两条独立来源同意；
4. 其中至少一条证据为强证据（`importance >= 80`）；
5. 达标后才替换当前事实，并保留替换前快照；
6. 控制中心可回滚；
7. 删除来源消息时同步删除对应反馈证据，避免备份恢复后复活。

通过场景：

- 单条纠错不覆盖旧偏好；
- 两条不同来源、其中一条强证据时晋升；
- 回滚恢复旧事实；
- 无来源或伪造来源不进入记忆；
- 关闭记忆保存的群友不进入证据账本。

仍需真实群反馈补充：

- 反讽和玩笑的弱/强证据判断；
- 多名群友意见冲突时的事实仲裁；
- 长期形成的群梗能否在合适时机自然复用。

## 记忆检索评测

FTS5 索引同步 `chat_events` 的插入、更新和删除。中文查询规则：

- 三字及以上词使用 FTS5 trigram 候选；
- 两字短词继续使用确定性的包含匹配；
- 多词使用 OR 候选后按词长评分；
- 所有结果仍受当前对话、来源授权、角色和时间范围约束。

离线验证了索引插入、文本更新、成员删除和数据库重开，不把 FTS 命中绕开现有权限边界。

## 发送评测

每次真实发送先写入持久 `delivery_intent`：

```text
prepared -> sending -> accepted
                    -> uncertain
                    -> failed
```

`accepted` 必须来自 OneBot API 的调用成功；进程崩溃、上下文失效或 socket 异常归为 `uncertain`。同一来源消息、目标和相同内容重复执行时：

- 已接受：不再发送；
- 发送中或不确定：不盲目重发；
- 失败：保留记录，仍由上层明确决定是否人工处理。

## 执行方式

开发期间使用定向测试：

```powershell
node --test topic.test.mjs wake.test.mjs dialogue.test.mjs memory.test.mjs production.test.mjs viewer.test.mjs
```

最终验收前再运行一次完整 Node 与 Python 测试。完整通过代表代码边界满足场景，不等于真实群自然度、QQ 平台稳定性或豆包网页兼容性已经得到保证。
